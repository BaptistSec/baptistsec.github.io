Checking CSV Structure in Python

Check whether each CSV data record has the same number of fields as its header. Read the limits before using the result.

You need Python 3.10 or later, a plain-text editor and a command window. No extra packages. Examples are fictional. Sources checked 7 October 2026. Tested locally with Python 3.10.12.

Printed code may wrap long lines. Copy the program from the web page or its original .py file, not from this printout.

1. Create a small CSV file

CSV means comma-separated values: a text table. This guide uses commas between fields and double quotes around a field that contains a comma or line break. Two double quotes inside a quoted field represent one quote. Save this fictional example as Practice.csv using UTF-8, a common way to store text:

Name,Team
Alice,Support
Bob,"Repairs, workshop"
Cara

The first record names the columns. Header names must not be blank or repeated with exactly the same spelling. They are not trimmed or changed: Name, name and Name are different names. This is a deliberate rule, not proof they mean different things.

2. Save the complete program

Save this as CheckCsv.py in the same folder. It reads a saved file only. It does not upload, modify or repair that file. Code panels scroll sideways on narrow screens so the original lines are preserved.

import csv as Csv
import io as Io
import sys as Sys
from pathlib import Path


def CheckCsv(FileName):
    with Path(FileName).open("rb") as Input:
        Data = Input.read(1048577)
    if len(Data) > 1048576:
        raise ValueError("input exceeds 1 MiB")
    Text = Data.decode("utf-8-sig")
    Csv.field_size_limit(65536)
    Reader = Csv.reader(Io.StringIO(Text, newline=""), strict=True)
    try:
        Header = next(Reader)
    except StopIteration:
        raise ValueError("empty input") from None
    if not Header or any(not Name.strip() for Name in Header):
        raise ValueError("header contains a blank name")
    if len(Header) != len(set(Header)):
        raise ValueError("header contains repeated names")
    Good = 0
    Bad = 0
    for Number, Row in enumerate(Reader, start=1):
        if Number > 1000:
            raise ValueError("more than 1000 data records")
        if len(Row) != len(Header):
            Bad += 1
            print(f"Record {Number}, ending at line {Reader.line_num}: expected {len(Header)} fields, found {len(Row)}")
        else:
            Good += 1
    print(f"Columns: {len(Header)}; matching records: {Good}; mismatched records: {Bad}")
    return 1 if Bad else 0


def Main():
    if len(Sys.argv) != 2:
        print("Usage: python3 CheckCsv.py input.csv", file=Sys.stderr)
        return 2
    try:
        return CheckCsv(Sys.argv[1])
    except (OSError, UnicodeError, ValueError, Csv.Error) as Error:
        print(f"Check stopped: {Error}", file=Sys.stderr)
        return 2


if __name__ == "__main__":
    raise SystemExit(Main())

3. Run the check

Open a command window in that folder. Use your installation's Python 3 command if it is not named python3. Quote a path containing spaces.

python3 CheckCsv.py Practice.csv

Expected output:

Record 3, ending at line 4: expected 2 fields, found 1
Columns: 2; matching records: 2; mismatched records: 1

The header is not a data record. A quoted field with a line break is still part of one record, so a record number and its physical ending line can differ. This report checks the number of fields, not their values.

4. Test both outcomes

Add ,Stores after Cara and run again. Expected summary:

Columns: 2; matching records: 3; mismatched records: 0

Save these separate files and test them too:

  • Duplicate.csv, containing Name,Name: stopped for repeated header names.
  • BlankHeader.csv, containing Name,: stopped for a blank header name.
  • Add an empty line between data records: it is a zero-field mismatch, not silently skipped. A normal final line ending does not add a record.
  • Broken.csv, containing an unfinished quoted field: stopped with a CSV reading error.

To test the field-length boundary, save this short test maker as MakeFieldTests.py in a new practice folder. Copy your CheckCsv.py into that folder too. Open a command window in that folder. The test maker creates two new fictional files and refuses to overwrite an existing file. Run it, then check both files. The 65,536-character field should complete; the 65,537-character field should stop.

from pathlib import Path

for Size in (65536, 65537):
    with Path(f"Field{Size}.csv").open("x", encoding="utf-8") as Output:
        Output.write("Value\n" + "x" * Size + "\n")
python3 MakeFieldTests.py
python3 CheckCsv.py Field65536.csv
python3 CheckCsv.py Field65537.csv

Return to your original practice folder before running the following tests. The contents of Broken.csv for the unfinished-quote test:

Name,Team
Alice,"Support
python3 CheckCsv.py Duplicate.csv
python3 CheckCsv.py BlankHeader.csv
python3 CheckCsv.py Broken.csv
python3 CheckCsv.py DoesNotExist.csv

The missing-file test should stop rather than print a completed summary. Python or operating-system error details may vary.

5. Understand the result and limits

An exit code is a small result number a command window or another program can check: 0 means the check completed with all field counts matching; 1 means it completed with mismatches; 2 means the command or reading stopped. A file with only a valid header completes with zero data records. Empty values in data fields are allowed when the field count matches.

A late reading or limit error can follow printed mismatch lines. Those earlier lines are partial output, not a completed verdict. Require the final summary and a completed exit code before treating a run as complete.

The program accepts UTF-8 with or without an initial byte-order marker (BOM), a small encoding marker. It reads at most 1 MiB (mebibyte), exactly 1,048,576 bytes, and permits at most 1,000 data records. Each field may contain at most 65,536 characters. A field of 65,537 characters stops the run even when the whole file fits the separate 1 MiB byte limit. It uses the default comma/double-quote format with strict reading enabled; it does not recognise every CSV variation or reject every unusual quote pattern. A semicolon-separated file can be read as one column, so a matching count does not prove the intended format was recognised.

It does not check required column names, types, dates, totals, duplicated data, formulas or whether an import is safe. It is not a spreadsheet security scanner. Use a small saved copy that will not change during the check. Do not run unknown downloaded code without reviewing it. If you save the output, use a new filename: redirecting output over the input can empty it before Python reads it. Keep reports and file paths private when they concern work.
